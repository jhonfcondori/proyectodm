## Code revert

ProyectoDM squash-merges PRs into `dev`, so the commit that lands on `dev` is a regular
(non-merge) commit and `git revert -m 1` would fail with "mainline was specified but commit is not a merge".
Use the squash merge SHA recorded above:

```bash
git switch dev
git revert 67903c7c8452f4495fa36a369e6b1a60b2ab4d3c
git push origin dev
```

If the merge was not pushed yet:

```bash
git reset --hard pre-merge-pr-1
```

## Database revert

Stop the API, then remove the initial SQLite database. There is no pre-existing backup to restore.

```bash
rm -f apps/api/prisma/dev.db apps/api/prisma/dev.db-journal apps/api/prisma/dev.db-wal
npm run db:generate
```

PowerShell equivalent:

```powershell
Remove-Item -LiteralPath apps/api/prisma/dev.db -Force -ErrorAction SilentlyContinue
npm run db:generate
```

Recreating the database later:

```bash
npm run db:migrate
```

If the database already contains real campaign data, **do not delete it**. Restore a verified backup with
`npm run db:restore -- --file <backup.db> --yes` and follow `docs/REVERT-PLAYBOOK.md`.
